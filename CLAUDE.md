# The Roland Team — Las Vegas Real Estate Site

A from-scratch, SEO- and AI-reach-optimized real estate marketing site for
The Roland Team (Las Vegas & Henderson luxury real estate). Built to rank
organically for community/neighborhood and buyer/seller search terms.

## Stack
- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS v4** (theme tokens in `src/app/globals.css`)
- Fully **static / SSG** — every page prerenders to HTML for speed + SEO
- Deploy target: **Vercel**

## Structure
- `src/lib/site.ts` — global site config (name, URL, phone, nav). **Update contact + URL before launch.**
- `src/lib/schema.ts` — JSON-LD builders (RealEstateAgent, BreadcrumbList, FAQPage)
- `src/content/communities.ts` — community/neighborhood pages (the main traffic engine)
- `src/content/guides.ts` — buyer/seller/relocation guides
- `src/components/` — Header, Footer, Container, CommunityCard, JsonLd
- `src/app/communities/[slug]` — dynamic community pages w/ metadata + structured data
- `src/app/guides/[slug]` — dynamic guide pages
- `src/content/portal.ts` — Client Portal journeys (buyer/seller stages + tasks) and vendor categories
- `src/lib/portal/` — portal state (`store.ts`, browser-local), CRM engagement events (`track.ts`), progress math
- `src/components/portal/`, `src/app/(homeowner)/portal/` — the client hub (dashboard, journey, saved, numbers, pros). Roland Team-branded and noindex, like the homeowner dashboards; reached by invite link, not the marketing nav.
- `src/app/admin/clients` — internal portal dashboard (roster from FUB, hub-link builder, signal playbook); `src/lib/portal/roster.ts` is its server-side FUB read
- `src/lib/offers/`, `src/app/api/slack/`, `src/content/offerDefaults.ts` — the **Offer Machine**: an agent types a plain-English request in a Slack channel → Claude *reads* it into fields → code (`terms.ts`) applies defaults, finds what's missing, validates → one confirmation card → on Confirm, a terms sheet + cover email in TransactionDesk field order. Needs **no TransactionDesk logins** and sends nothing. `offerDefaults.ts` holds the team's real standard terms (from the transaction coordinator). After Confirm the bot also posts signed, expiring links to filled **forms drafts** (`src/lib/offers/forms/`, `src/lib/offers/rpa/`): Duties Owed, Supplemental list, BBRA, and the RPA. The blank GLVAR/NRED PDFs and the brokerage config (broker, agent license numbers) are NOT in this public repo: they live in the private Vercel Blob store and are uploaded via `/api/admin/offers-forms` (key = `ADMIN_TOKEN` or `OFFER_FORMS_KEY`). See `docs/offer-machine.md`; `npm run offers:test`. (`src/app/api/offers/worker/` is a switched-off drafting-machine queue, `OFFER_QUEUE_ENABLED`.)
- `src/app/sitemap.ts`, `src/app/robots.ts` — auto-generated
- `legacy/` — the old standalone HTML pages (pre-rebuild), kept for reference

## Adding content
- **New journey step / vendor:** add to `src/content/portal.ts`. Task ids are storage keys for client progress — **never renumber or reuse an id**.
- **New community:** add an object to `communities` in `src/content/communities.ts`. It automatically gets a page, sitemap entry, footer link, and structured data.
- **New guide:** add an object to `guides` in `src/content/guides.ts`.
- Keep facts general/verifiable; pricing is approximate — always route buyers to "contact for current availability."
- **SEO rules:** every page needs a unique `seoTitle` (~60 chars) and `seoDescription` (≤155 chars). Follow Fair Housing guidelines — describe places by objective attributes, never demographics.

Optional for most calls, **required** to register webhooks (`/api/admin/fub-webhook-setup`) — FUB 403s webhook registration with "X-System-Key header missing" otherwise. Request a system name + key from Follow Up Boss and set both; every FUB call then sends them.
- `ADMIN_TOKEN` — required for `/admin/sellers` and `/admin/clients`; gates all client data served to them. Also gates the read-only `/api/admin/audit-homeowners?key=…` endpoint, which buckets the homeowner store by eligibility (eligible / invalid-email / out-of-state / unknown-location) and reports counts, samples, and the top out-of-state states — it writes nothing. It also authorizes a **manual run of the homeowner digest** — `/api/cron/homeowner-digest?key=ADMIN_TOKEN` — which **dry-runs by default** (`CRON_SECRET` is write-only in Vercel, so the admin key is how you run the warm-up by hand); add `&send=1` to actually refresh values and send that batch.

The digest also re-checks eligibility at send time, so ineligible rows already in the table are never mailed. Keep this modest to protect a young sending domain.
- `HOMEOWNER_DIGEST_COLD_CAP` — warm-first guardrail (default **3**). The digest holds back any contact who has already received this many value emails and has **never** opened their dashboard, so the recurring send stops burning deliverability on people who never engage. Engaged contacts (any dashboard view) and newer contacts still inside their first few touches keep going. `?all=1` on the digest ignores the guardrail and reaches the whole eligible list (use for a deliberate win-back); `?engaged=1` is the stricter opposite (dashboard-openers only). The dry-run / cron JSON reports `skippedCold` and `segment.warmFirst`.
- `SELLER_AUTO_TAG` / `SELLER_AUTO_NEW_DAYS` / `SELLER_AUTO_MAX_PER_RUN` — seller home-report auto-send (`src/lib/homeowners/sellerAuto.ts`). A FUB contact tagged `Seller` (override name with `SELLER_AUTO_TAG`) with a valid email and a Nevada address+ZIP gets the welcome email with their private dashboard link, then a `Home Report Sent` tag so they're never mailed twice. Fires for NEW leads (created within `SELLER_AUTO_NEW_DAYS`, default 3) via the FUB webhook / 30-min poll, and for ANY lead when an agent adds the tag (needs the `peopleTagsCreated` webhook — re-run `/api/admin/fub-webhook-setup?key=…&action=install`). `SELLER_AUTO_MAX_PER_RUN` (default 25) caps sends per run and `SELLER_AUTO_DAILY_CAP` (default 40) is a hard per-day budget (Las Vegas midnight reset; over-budget leads wait for the next day while still inside the new-lead window). Requires `HOMEOWNER_EMAIL_ENABLED="true"`. Test one contact: `/api/admin/seller-report?key=ADMIN_TOKEN&personId=<fub id>` (dry-run; add `&send=1`).
- `SELLER_BACKFILL_ENABLED` / `SELLER_BACKFILL_PER_RUN` — throttled back-catalog invite for the EXISTING `Seller`-tagged database (the real-time path only invites new/newly-tagged leads). `/api/cron/seller-backfill` (daily cron) sweeps all `Seller`-tagged FUB contacts and runs each through the same `maybeSendSellerReport(manual:true)` path — idempotent (`Home Report Sent` claim), eligibility-gated (valid email + NV ZIP), unsubscribe-aware, and bounded by the shared `SELLER_AUTO_DAILY_CAP`. **OFF by default**: the scheduled run no-ops unless `SELLER_BACKFILL_ENABLED="true"`. `SELLER_BACKFILL_PER_RUN` (default 10) caps sends per run — keep low and ramp slowly to protect a young sending domain. ## Gotchas (Repliers / estimator)
- **`class` is NOT detached-vs-attached on GLVAR.** Detached homes in an HOA/PUD are filed under `CondoProperty`, so filtering the comp query by `class=ResidentialProperty` (for "Single Family") returned an empty bucket across ~half the valley (Summerlin, Anthem, Green Valley, Southern Highlands, Mountain's Edge). `src/lib/idx/estimate.ts` no longer sends `class`; it pulls all comps and classifies each in-app (`styleWantFor` / `styleTextOf` / `matchesStyle`), **failing open** — a comp is dropped only when its own style text positively reads as attached. The style field names vary by MLS; `/api/admin/estimate-test?...&comps=1` dumps the `byStyle` map + sample `details` to find the real ones.
- **Repliers `status` takes a single value.** `status=A,U` 400s — use one (`U` for sold comps).
- **The `/estimates` (AVM) POST requires a `details` object** (beds/baths/sqft); omitting it 400s.

## Homeowner engine lives on home.therolandteam.com
- Every homeowner-facing link, page and email uses `homeownerBrand.baseUrl`, which falls back to `https://home.therolandteam.com` (`HOMEOWNER_ORIGIN`) — **never** `site.url`. `site.url` is the rolandluxury.com marketing site and stays that way; do not point homeowner links, phone numbers or admin checks at it.
- With `MARKETING_HOSTS` set, `/dashboard`, `/embed` and `/admin` on a rolandluxury.com host 308 to the homeowner host (middleware). API routes are never redirected.

## Consent & contact permissions
- The homeowner model carries three nullable consent fields (`emailConsent`, `callTextConsent`, `dnc` — `src/lib/homeowners/store.ts`). **`undefined`/NULL = unknown**, treated as an existing relationship and still mailable (so the imported database and legacy rows are unaffected). `false` is an explicit opt-out.
- **The value digest honors an explicit email opt-out:** `listDueForEmail` excludes `emailConsent === false` (memory) / `email_consent IS DISTINCT FROM false` (Postgres). It does **not** gate on `dnc` — DNC is a calls/texts flag; CAN-SPAM email with an unsubscribe link is still allowed.
- **Web forms capture consent as separate, optional, unchecked checkboxes** (Fair-Housing / TCPA-aligned): `LeadForm` and `CashOfferForm` collect an ongoing-email opt-in and a call/text opt-in. The "track my home" step (`HomeEstimator`) sets `emailConsent: true` because requesting value updates *is* the opt-in to that stream.
- **Consent reflects to FUB as tags** the team's automations/agents can key on: **`Email Opt-In`** and **`Call/Text OK`** (added in `/api/lead` and `/api/homeowners/cash-offer`). `dnc` is set by a DNC scrub / import / admin, not a public form.
- **DNC scrub:** `/admin/dnc?key=ADMIN_TOKEN` is a paste-and-apply page — paste the phone numbers that came back ON the Do Not Call registry, Preview (read-only match count), then Apply to set `dnc = true` on matching homeowners (phone-matched on the last 10 digits). API: `POST /api/admin/dnc/import?key=ADMIN_TOKEN` (dry-run; `&apply=1` writes) accepting raw text/CSV or JSON `{phones|text}`. DNC marks route the contact email-only in Seller Triage; the value digest is unaffected (email with an unsubscribe link is allowed). The pasted list is matched, never stored — **never commit a scrub file to this public repo.**
- **Seller triage:** `/admin/triage?key=ADMIN_TOKEN` (`src/lib/homeowners/triage.ts`) buckets homeowners Ready / Review / Skip with relationship, consent badges, and a recommended FUB plan (maps to `docs/fub-action-plans.md`).
- **Recipients management:** `/admin/recipients?key=ADMIN_TOKEN` has a per-contact **Manage** column, and its search matches name / email / **street address** / city / ZIP / phone. **Send report** (`POST /api/admin/recipients/send-report`) refreshes the estimate and emails that one homeowner their value report on demand (needs `HOMEOWNER_EMAIL_ENABLED="true"`; refuses an unsubscribed contact). **Remove** / **Delete** (`POST /api/admin/recipients/remove`): **Remove** unsubscribes (`subscribed=false`: stops emails, keeps the record + history, and the FUB import preserves it so the contact stays off). **Delete** hard-deletes the row AND records its token in `homeowner_blocklist`, which `upsertContacts` consults so the automated FUB import (sync / poll / webhook) never re-creates it — remember the homeowner store is a mirror of FUB, so a plain delete without the block-list would be undone by the next sync. A deliberate single write (a person self-submitting on the site, via `upsert`) is **not** blocked, so a genuine fresh opt-in can still return.
